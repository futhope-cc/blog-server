# 用户模块实现计划

## Context（背景）

项目《个人技术博客与项目展示平台》后端已完成依赖集成（Spring Boot 4.1.0 / Java 17 / MyBatis-Plus 3.5.17 / sa-token 1.45.0 / springdoc 3.1.0 / mapstruct 1.5.5），但尚无任何业务代码，也缺少所有基础设施类。本次目标是实现需求文档 5.1「用户管理」模块——管理员登录、登出、获取当前用户信息、修改密码，外加完整用户 CRUD 管理（分页查询、新增、编辑、删除、重置密码）。

由于项目是第一个业务模块，必须**一并搭建用户模块运行所依赖的全部基础设施**（统一返回、异常处理、BaseDomain、MyBatis-Plus 配置、sa-token 拦截器、CORS、密码工具等），这些基础设施后续模块将直接复用。

**用户决策**：接口范围=完整用户 CRUD；密码加密=hutool-crypto 的 BCrypt。

## 关键发现（实施前必修复）

探查 pom.xml + 官方文档核对后发现 4 个阻塞性问题，必须在编码前修正：

1. **sa-token starter 用错了**：当前是 `sa-token-spring-boot-starter`（SB2 专用），SB4.1.0 必须用 1.45.0 新增的 `sa-token-spring-boot4-starter`，否则行为不可预期。
2. **mapstruct-processor 缺失**：`annotationProcessorPaths` 只有 lombok，Converter 实现类不会生成，启动报 `No qualifying bean of type 'UserConverter'`。
3. **MyBatis-Plus 分页插件已分离**：3.5.9 起 `PaginationInnerInterceptor` 移到 `mybatis-plus-jsqlparser`，3.5.17 必须单独引入，否则分页不生效。
4. **SB4 用 Jackson 3**：sa-token 的 Redis 序列化需配 `sa-token-jackson3`，否则可能 `ClassCastException`。

## 一、pom.xml 改动

### 1.1 修复 sa-token starter
```xml
<!-- 删除 sa-token-spring-boot-starter，改为 -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-spring-boot4-starter</artifactId>
    <version>1.45.0</version>
</dependency>
<!-- sa-token-redis-template:1.45.0、commons-pool2 保持不变 -->
<!-- 显式声明 Jackson3 序列化（适配 SB4 的 Jackson 3） -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-jackson3</artifactId>

</dependency>
```

## 二、基础设施类（用户模块运行前置，新建）

基础包 `com.cc.blogserver`，所有类按规范目录放置。

| 文件 | 职责要点 |
|---|---|
| `common/Result.java` | 统一返回 `{code,message,data}`；静态工厂 `success()`/`success(data)`/`fail(ErrorCode)`/`fail(code,msg)` |
| `common/PageResult.java` | 分页返回，含 `records/total/current/size` |
| `exception/ErrorCode.java` | 枚举：SUCCESS(0)、PARAM_INVALID(400)、UNAUTHORIZED(401)、FORBIDDEN(403)、NOT_FOUND(404)、USERNAME_OR_PASSWORD_ERROR(1001)、USER_NOT_EXIST(1002)、USER_DISABLED(1003)、USERNAME_EXISTS(1004)、OLD_PASSWORD_ERROR(1005)、CANNOT_DELETE_SELF(1006)、CANNOT_DELETE_LAST_ADMIN(1007)、SYSTEM_ERROR(500) |
| `exception/BusinessException.java` | 持 `ErrorCode` + 可选自定义 message；`throw new BusinessException(ErrorCode.XXX)` |
| `handler/GlobalExceptionHandler.java` | 处理：BusinessException、`NotLoginException`(按 5 种 type 转 msg，返回 401)、`NotPermissionException`/`NotRoleException`(403)、`MethodArgumentNotValidException`(取首个 fieldError，400)、`ConstraintViolationException`(400)、`HttpRequestMethodNotSupportedException`(405)、`NoHandlerFoundException`(404)、`Exception` 兜底(log.error 全栈，500) |
| `domain/BaseDomain.java` | `id`(`@TableId(type=IdType.ASSIGN_ID)` 雪花 Long)、`createTime`(`@TableField(fill=INSERT)`)、`updateTime`(`@TableField(fill=INSERT_UPDATE)`)，`LocalDateTime`；全局 Long→String 序列化避免前端精度丢失 |
| `config/MybatisPlusConfig.java` | `MybatisPlusInterceptor` + `PaginationInnerInterceptor(DbType.MYSQL)`(setMaxLimit=500)；`MetaObjectHandler` 自动填充 createTime/updateTime |
| `config/SaTokenConfig.java` | `WebMvcConfigurer.addInterceptors` 注册 `SaInterceptor(handle->StpUtil.checkLogin())`，拦截 `/admin/**`，放行 `/admin/login`、`/doc.html`、`/swagger-ui/**`、`/v3/api-docs/**`（路径不含 context-path `/api`） |
| `config/CorsConfig.java` | `addCorsMappings("/**")`，`allowedOriginPatterns("*")`、`allowCredentials(true)`、methods=GET/POST/PUT/DELETE/OPTIONS |
| `config/SpringDocConfig.java` | `OpenAPI` Bean，title/description/version |
| `constant/RedisKey.java` | 枚举统一管理 key，`format(args...)`；用户模块暂用 `USER_INFO("user:info:%s")` 占位 |
| `utils/PasswordUtils.java` | 封装 hutool `cn.hutool.crypto.digest.BCrypt`：`hash(plain)`(cost=10)、`verify(plain,hashed)`；private 构造，final 类 |

**密码工具放 utils 的依据**：规范第 17 条「禁止随意创建 Utils」指通用方法散落，而密码加密是登录/改密/新增/重置共用能力，符合「通用逻辑抽取公共方法」，合理。

## 三、user 表 DDL + 数据初始化

### 3.1 表名 `sys_user`（遵循规范第 12 条示例，`user` 是 SQL 保留字；Domain 类仍叫 `User`，用 `@TableName("sys_user")` 映射）

文件 `src/main/resources/sql/init.sql`：
```sql
CREATE TABLE IF NOT EXISTS `sys_user` (
  `id`          BIGINT       NOT NULL                   COMMENT '主键ID(雪花)',
  `username`    VARCHAR(50)  NOT NULL                   COMMENT '用户名',
  `password`    VARCHAR(100) NOT NULL                   COMMENT '密码(BCrypt)',
  `nickname`    VARCHAR(50)  NULL                       COMMENT '昵称',
  `avatar`      VARCHAR(255) NULL                       COMMENT '头像URL',
  `email`       VARCHAR(100) NULL                       COMMENT '邮箱',
  `status`      TINYINT      NOT NULL DEFAULT 1         COMMENT '状态:0禁用 1正常',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统用户表';
```
逻辑删除暂不加（物理删除，避免与 username 唯一索引冲突）；未来需审计再改 `(username,deleted)` 联合唯一。

### 3.2 默认管理员初始化（不写死 BCrypt 哈希）

新增 `config/DataInitializer.java` 实现 `ApplicationRunner`：启动时若 `sys_user` 表为空，用 `PasswordUtils.hash("123456")` 实时生成哈希插入默认管理员（username=admin, nickname=管理员, status=1）。避免 BCrypt 哈希写死不可靠的问题，部署友好。

## 六、关键业务流程

1. **登录**：按 username 查用户→null 抛 `USERNAME_OR_PASSWORD_ERROR`（防枚举，不提示「用户不存在」）→status=0 抛 `USER_DISABLED`→`PasswordUtils.verify` 失败抛 `USERNAME_OR_PASSWORD_ERROR`→`StpUtil.login(userId)`→返回 `LoginResponse(tokenName, tokenValue, userInfo)`。日志只打 userId，禁打密码。
2. **修改密码**：`StpUtil.getLoginIdAsLong()` 取当前用户→`verify(oldPassword)` 失败抛 `OLD_PASSWORD_ERROR`→`hash(newPassword)` 更新。
3. **新增用户**：`exists(username)` 抛 `USERNAME_EXISTS`→`hash(initialPassword)`→insert。
4. **删除用户保护**：`id == 当前登录id` 抛 `CANNOT_DELETE_SELF`；`selectCount(status=1) <= 1` 抛 `CANNOT_DELETE_LAST_ADMIN`；本项目无角色表，启用用户即视为管理员。
5. **空值判断**：一律 `Objects.isNull` / `CollectionUtils.isEmpty`，禁止 `== null`。

## 七、实施顺序

1. 改 pom.xml（§1）→ `mvn clean compile` 验证依赖解析与 mapstruct 处理器加载。
2. 建基础设施（§2 全部）。
3. 建表 SQL + DataInitializer（§3）。
4. 建用户模块：Domain → Mapper → DTO → Converter → Service/Impl → Controller（§4）。
5. `mvn compile` 验证 `target/generated-sources/annotations` 下生成 `UserConverterImpl`。
6. 启动应用，确认 DataInitializer 插入默认 admin。
7. 端到端验证（见 §8）。

## 八、验证方式（端到端）

1. **编译**：`mvn clean compile` 通过，且 `target/generated-sources/annotations/com/cc/blogserver/converter/UserConverterImpl.java` 存在。
2. **启动**：应用无报错启动；查 `sys_user` 表确认 admin 记录已初始化。
3. **swagger-ui**：访问 `http://localhost:8081/api/swagger-ui.html`，看到「管理员鉴权」「用户管理」两个 Tag 及全部接口。
4. **登录**：POST `/api/admin/login`，body `{"username":"admin","password":"123456"}`，返回 tokenName/tokenValue。
5. **鉴权**：不带 token GET `/api/admin/user/info` → 返回 401「未登录」；带 Header `satoken: <tokenValue>` 再请求 → 返回用户信息。
6. **改密**：PUT `/api/admin/user/password` 改密码后，旧密码登录失败、新密码登录成功。
7. **CRUD**：新增用户→分页查询能看到→编辑→重置密码→删除（删除自己或最后一个管理员被拦截，返回对应业务码）。

## 九、坑点备忘

- sa-token 拦截器路径不含 context-path `/api`；Controller mapping 也不带 `/api`，否则变 `/api/api/admin/...`。
- `allowCredentials(true)` 必须配 `allowedOriginPatterns`，不可用 `allowedOrigins("*")`。
- CORS 需在 sa-token 拦截器前生效（`addCorsMappings` 默认在拦截器前处理，正常）。
- Long 雪花 ID 前端精度：全局 Jackson 3 配 Long→String（SB4 用 Jackson 3 定制器，实现时确认 API）。
- sa-token `is-share=false`+`is-concurrent=true`：多端登录各自独立 token，均为有效。
- hutool-crypto 必须用 5.8.47，避开旧版 CVE。
- BCrypt 哈希每次不同（随机盐），不可手写固定串；用 DataInitializer 实时生成最可靠。
