# 个人博客后端开发计划

版本：V1.0
作者：XXX
日期：2026-08-03

> 本文档基于《个人技术博客与项目展示平台需求文档》及项目 Spring Boot 开发规范，对后端开发进行分阶段规划。


# 3. 阶段 0：基础设施搭建（地基，必须先做）

> 目标：让项目"能跑、能连库、能返回统一结果、能鉴权、能上传文件、能看 API 文档"。
> 这一阶段不写业务，只搭骨架。

## 3.1 依赖补齐（pom.xml）

需新增：

```xml
mybatis-plus-spring-boot3-starter      <!-- 需确认 SB4 兼容版本 -->
mysql-connector-j
spring-boot-starter-data-redis
spring-boot-starter-validation
jjwt-api / jjwt-impl / jjwt-jackson    <!-- JWT -->
minio                                  <!-- 对象存储 -->
springdoc-openapi-starter-webmvc-ui    <!-- 或 knife4j，API 文档 -->
commons-lang3 / hutool-all             <!-- 工具类（二选一或都用） -->
```

## 3.2 配置文件

- 将 `application.properties` → `application.yaml`
- 拆分多环境：`application.yaml`（公共）+ `application-dev.yaml` + `application-prod.yaml`
- 配置项：数据源、Redis、MyBatis-Plus、MinIO bucket、JWT secret/过期、文件上传限制

## 3.3 全局基础设施代码（按规范目录）

| 类/文件 | 位置 | 职责 |
|---|---|---|
| `Result<T>` | `dto/responseDTO` 或 `common` | 统一返回 `{code,message,data}` |
| `PageResponse<T>` | `dto/responseDTO` | 分页统一返回 |
| `ErrorCode` | `exception` | 错误码枚举 |
| `BusinessException` | `exception` | 业务异常 |
| `GlobalExceptionHandler` | `handler` | 全局异常 → Result |
| `BaseDomain` | `domain` | 公共字段 id/createTime/updateTime，自动填充 |
| `MybatisPlusConfig` | `config` | 分页插件 + 自动填充处理器 |
| `RedisConfig` | `config` | 序列化配置 |
| `RedisKey` | `constant` | Key 统一管理（禁止拼接） |
| `JwtUtils` | `utils` | 生成/解析/校验 token |
| `JwtInterceptor` | `interceptor` | 后台接口鉴权 |
| `WebMvcConfig` | `config` | 注册拦截器 + CORS |
| `MinioConfig` / `MinioUtils` | `config` / `utils` | 文件上传 |
| `KnifeConfig` | `config` | API 文档 |

## 3.4 数据库初始化

- 在 `src/main/resources` 下建 `sql/init.sql`，按规范补全字段（所有表加 `create_time` + `update_time`）
- 建表顺序：`user` → `category` → `tag` → `article` → `article_tag` → `project` → `comment`

## 3.5 阶段 0 验收标准

- 启动不报错、连上 MySQL/Redis
- 访问任意不存在接口返回统一 `Result` 错误结构
- Knife4j 文档页可打开
- 跑通一次"假接口 + JWT 拦截"联调

# 4. 阶段 1：MVP 核心（文章系统 + 后台管理）

> 对应需求文档第一阶段。这是后端的主体，建议**按依赖顺序**逐模块推进。

## 4.1 实现顺序（强烈建议按此顺序，避免返工）

```
用户登录(JWT) → 分类 → 标签 → 文章 → 文件上传 → 前台只读接口
```

## 4.2 用户管理（管理员登录）

- 表：`user`
- 接口：`POST /api/admin/login`（返回 token）、`POST /api/admin/password`（改密）
- 要点：密码 BCrypt 加密；登录成功签发 JWT；提供"修改密码"
- 产物：UserController / Service / UserServiceImpl / UserMapper / User(domain) / LoginRequest / LoginResponse / UserConverter

## 4.3 分类管理

- 表：`category`
- 接口：CRUD（后台）+ `GET /api/category/list`（前台只读）
- 要点：`sort` 排序字段；删除前校验是否有关联文章

## 4.4 标签管理

- 表：`tag` + `article_tag`（多对多）
- 接口：CRUD（后台）+ 前台列表
- 要点：文章-标签关系表维护，文章保存时同步更新

## 4.5 文章管理（核心）

- 表：`article`
- 接口：
    - 后台：`POST /api/admin/article`（新增/草稿）、`PUT`（编辑）、`DELETE`、发布/下线
    - 前台：`GET /api/article/list`（分页+分类+标签筛选）、`GET /api/article/{id}`（详情）
- 要点：
    - status 状态机：草稿 / 已发布 / 已下线
    - 前台只查"已发布"
    - 详情接口 +1 浏览量（先 Redis 计数，定时/异步落库，避免高频写库）
    - 列表查询用 MyBatis-Plus 分页 + 条件构造器

## 4.6 文件管理

- 接口：`POST /api/file/upload`（图片/附件）
- 要点：MinIO 上传，返回可访问 URL；限制类型与大小；图片可按日期分目录

## 4.7 阶段 1 验收标准

- 管理员能登录拿到 token
- 能在后台发布一篇带分类、标签、封面的 Markdown 文章
- 前台能分页浏览、按分类/标签筛选、看详情（Markdown 正文直出）
- 能上传封面图并引用

# 5. 阶段 2：内容运营（评论 + 搜索 + 统计）

> 对应需求文档第二阶段。在 MVP 之上叠加运营能力。

## 5.1 评论模块

- 表：`comment`（需补：`nickname`、`email`、`website`、`avatar`，因为是游客评论）
- 接口：
    - 前台：`POST /api/comment`（发表）、`GET /api/comment/list?articleId=`（树形拉取）
    - 后台：`GET /api/admin/comment`、审核通过/拒绝/删除
- 要点：`parent_id` 构建树形；status 审核状态；前台只展示已通过；可选敏感词过滤

## 5.2 搜索

- 一期：MySQL `LIKE` 关键词搜索（标题+摘要+正文），接口 `GET /api/search`
- 二期（按需）：接入 Elasticsearch，支持高亮、分词
- 建议：一期够用，数据量大再升级，避免过早引入 ES

## 5.3 数据统计 Dashboard

- 接口：`GET /api/admin/dashboard`
- 指标：文章数、项目数、总浏览量、评论数、热门文章 Top N
- 要点：用 Redis 缓存统计结果，定时刷新；浏览量走 Redis 计数

## 5.4 SEO 与细节增强

- article 增 `slug`（友好 URL）、`meta_description`、`keywords`
- 详情接口返回上一篇/下一篇、相关文章

## 5.5 阶段 2 验收标准

- 游客能评论、后台能审核
- 全站关键词搜索可用
- Dashboard 数据准确且缓存生效

# 6. 阶段 3：AI 能力

> 对应需求文档第三阶段。属于扩展项，依赖外部 LLM 服务，建议在 1、2 稳定后再做。

- **AI 文章助手**：后台编辑时调用 LLM 辅助生成摘要、润色、起标题
- **AI 技术问答**：前台对话接口，流式返回（SSE）
- **AI 知识库**：基于已发布文章做 RAG（向量化 + 检索 + 生成）

技术要点：抽象 `LlmClient`（适配 OpenAI/国产模型）、向量库选型（Milvus/PGVector）、SSE 流式输出、Prompt 模板管理、调用限流与成本控制。

# 8. 工程规范（贯穿全程，必须遵守）

来源于项目 `.trae/rules/springboot-project-rule.md`：

- 分层严格：Controller 不写业务、Service 不返回 Entity、Mapper 不调 Service
- DTO 命名：`XxxRequest` / `XxxResponse`，Controller 禁止直接返回 Domain，禁用 `BeanUtils.copyProperties`，走 `Converter`
- 写操作 `@Transactional` 只放 Service 层
- 空值用 `Objects.isNull` / `CollectionUtils.isEmpty`，禁止 `== null` / `size()==0`
- Redis Key 用 `RedisKey.XXX.format()` 统一管理
- 异常转 `BusinessException(ErrorCode.XXX)`，禁止空 catch、禁止 `System.out.println`
- 日志带上下文：`log.info("article publish success, id={}", id)`，禁止打印密码/token
- Commit 规范：`feat: add article publish api`

# 9. 推荐执行节奏

| 步骤 | 内容 | 产出 |
|---|---|---|
| 第 1 步 | 阶段 0 全部 | 可运行的骨架 + Knife 文档 |
| 第 2 步 | 阶段 1.2~1.4 | 登录 + 分类 + 标签 |
| 第 3 步 | 阶段 1.5 + 1.6 | 文章 + 文件上传（MVP 完成） |

| 第 5 步 | 阶段 3 | AI 能力（可选） |

每一步都做到"能联调验收"再进入下一步，避免大爆炸式集成。
