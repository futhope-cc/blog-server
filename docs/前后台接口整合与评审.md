## 二、统一约定（依据后端编码规则）

### 2.1 通用

| 项 | 约定 |
|---|---|
| Base URL | 后台 `http://localhost:8081/api`；前台 `/api`（代理到后端，`/api` 是 context-path，**Controller 和拦截器路径都不带 `/api`**） |
| 统一返回 | `Result<T>`：`{ code, message, data }`，**`code=0` 成功** |
| id 类型 | **全部 string**（Long→String 防 JS 精度丢失，MapStruct 自动转换） |
| 时间格式 | ISO-8601，如 `2026-08-04T10:30:00`（LocalDateTime 默认序列化） |
| DTO 命名 | 请求 `XxxRequestDTO` / 响应 `XxxResponseDTO`；分页请求继承 `PageRequestDTO`，返回 `PageResult<T>` |
| Controller | `@RequestMapping` 只允许**单层前缀**（`/article`、`/category`…），方法路径写死；响应 id 用 String；类 `@Tag`、方法 `@Operation`、DTO 字段 `@Schema`、路径参数 `@Parameter` |
| 状态字段 | 一律 int 枚举并抽常量：用户 `0禁用/1正常`；文章 `0草稿/1发布/2下线` |

### 2.2 分页（统一 MyBatis-Plus 格式）

- 请求参数：`current`（页码，默认 1）、`size`（每页条数，默认 10），校验 `@Min(1)`。
- 响应 `data`：`{ "records": [], "total": 100, "current": 1, "size": 10 }`。

### 2.3 鉴权与错误码

- 后台所有接口（除登录）需请求头 `satoken: <tokenValue>`；401 时前端清登录态跳登录页。
- 前台只读接口无鉴权。`SaTokenConfig` 需新增拦截：`/article/**`、`/category/**`、`/tag/**`、`/project/**`、`/file/**`、`/stats/**`，并**放行前台只读路径**（见 3.2 标注）。
- 错误码：0 成功、400 参数校验失败、401 未登录、403 无权限、404 资源不存在、405 方法不支持、500 系统错误，业务码 1001~1007（用户）+ 新模块按需补充（如分类名已存在、分类下有文章不可删除、文章不存在等）。

### 2.4 方法语义

- `GET` 查询 / `POST` 新增 / `PUT` 整量更新 / `DELETE` 删除 / `PATCH` 局部更新（状态变更）。
- 动作型子资源用 `/{id}/action`：如 `PUT /article/{id}/status`、`PUT /user/{id}/password/reset`。
- 禁止动作动词路径：不用 `delete/{id}`、`update/{id}`。

## 三、接口合并与拆分决策

| 原接口 | 决策 | 理由 |
|---|---|---|
| `/admin/category/list` + `/admin/category/all` + 前台 `/category/list` | ✅ **合并**为 1 个 `GET /category/list` | 三者在数据上只是「是否带文章数」的区别；分类量少无需分页；后台管理页直接复用公开列表 |
| `/admin/tag/list` + `/admin/tag/all` + 前台 `/tag/list` | ✅ **合并**为 1 个 `GET /tag/list` | 同上 |
| `POST /admin/article`（用 body.id 区分新增/编辑） | ⛔ **拆分**为 `POST /article` + `PUT /article/{id}` | 方法语义混合，不符合 2.4；与其他模块风格统一 |
| 前台 `/article/list` vs 后台 `/article/page` | ⛔ **不合并** | 鉴权边界不同 + 数据范围不同（仅已发布 vs 全部状态）+ 字段范围不同（管理列表含 content 供回显） |
| 前台 `/project/list` vs 后台 `/project/page` | ⛔ **不合并** | 同上（featured 筛选、字段范围不同） |
| `/user/password`（改自己）vs `/user/password/reset/{id}`（重置他人） | ⛔ **不合并** | 语义不同（前者需旧密码）；仅统一请求体规范 |
| 前台文章详情 vs 后台编辑回显 | ⛔ **不合并** | 可见范围（仅发布 vs 任意状态）+ 副作用（前台详情浏览量+1，后台回显不应+1）。后台回显由管理分页 records 直接承载 content |

## 四、整合后接口设计

> 以下入参已按后端规则统一（分页 current/size、id string、状态 int、DTO 命名）。标记 🔓 为公开接口（SaTokenConfig 放行），其余需鉴权。

### 4.1 前台（公开）

| 方法 | 路径 | 说明 | 入参 |
|---|---|---|---|
| 🔓 GET | /article/list | 文章分页（仅已发布） | `ArticlePageRequestDTO`：current/size/categoryId/tagId/keyword |
| 🔓 GET | /article/{id} | 文章详情（仅已发布，浏览量+1） | 路径 id |
| 🔓 GET | /category/list | 分类列表（含已发布文章数，按 sort 升序） | 无 |
| 🔓 GET | /tag/list | 标签列表（含使用次数） | 无 |
| 🔓 GET | /project/list | 项目分页 | current/size + `featured`（1=仅首页精选，可选） |
| 🔓 GET | /project/{id} | 项目详情 | 路径 id |
| 🔓 GET | /profile | 关于我（个人简介/技术栈/社交链接） | 无 |

出参统一为 `Result<T>`，分页用 `PageResult<T>`，id 为 string。列表出参不含 `content`（详情才返回，避免大字段）。

### 4.2 后台（需鉴权）

#### 文章模块 /article

## 六、问题清单（按优先级）

### P0 —— 必须统一，否则前后端无法联调

1. `code` 语义：前台 mock `200` vs 后端 `0` → 统一 `0`。
2. 分页参数 `page/pageSize` → `current/size`；响应三种格式 → 统一 `{records,total,current,size}`。
3. id 类型：全部 string；时间格式：统一 ISO。
4. 后台文档补全错误码表（原只有 401）。

### P1 —— 影响功能完整性

5. 项目管理补 `featured`/`deployment` 入参。
6. 新增前台 `/profile` 接口（替代 About 复用项目列表）。
7. 文章接口拆分 `POST` + `PUT`，status 统一 int。
8. 分类/标签合并后，`SaTokenConfig` 需放行 `/category/list`、`/tag/list` 等公开路径（否则后台用不了下拉、前台直接 401）。

### P2 —— 规范一致性（可后置）

9. 用户模块路径 REST 化（`/user/update/{id}` → `/user/{id}` 等），需与已对接前端同步改造。
10. 重置密码请求体只保留 `newPassword`（拆独立 DTO）。
11. 新模块补充 ErrorCode 业务码（分类名已存在、分类下有文章不可删除、文章不存在等）。

## 七、实施建议

1. **先统一约定**：前台 mock 按第二章改造后，再对接真实后端。
2. **后台按依赖顺序落地**：分类/标签（建 `category/tag` 表）→ 文章（`article/article_tag` 表）→ 文件（本地磁盘存储、`file` 表）→ 项目（`project` 表）→ 统计。
3. **新增接口遵守**：`AGENTS.md` + `.trae/rules/springboot-project-rule.md` 19 条（统一 Result/PageResult、DTO 命名、converter 转换、手动逻辑删除 `is_delete`、springdoc 注解、SaTokenConfig 同步调整、日志带上下文）。
4. 本整合文档为唯一基准；原三份文档与新接口不一致时以本文为准。
